参考信息

支持的文件 iap_side.bin —— IAP 烧录文件（0x0 ~ 0x13FFFF，含 bootloader + 配置区 + 分区表 A + IAP 程序）
iap_cfg.bin —— 8KB 独立配置区
user.bin —— 用户程序（从 0x140000 开始的完整镜像，含分区表 B）
所有文件格式都会自动校验
烧录槽位 1. IAP 烧录文件 → 0x000000（iap_side.bin，1280KB 整片）
2. 用户程序 → 0x140000（user.bin，整段写入）
两个文件地址不重叠，可任意顺序烧录
用户程序镜像 ⚠️ 必须是单一文件，从 0x140000 开始：
0x140000 分区表 B　0x141000 0xFF 填充　0x150000 应用镜像
用 build_user_app.py 或 merge_user_app.py 生成（会合并分区表 B）
用户程序地址 不再硬编码，由设备上的分区表 B 的 OTA 槽决定：
槽 0 → user_app (ota_0)　槽 N → user_app_N (ota_N)
分区表 B 属用户程序工程，本工具连接设备时自动读回
多 OTA 槽 槽位布局由用户程序工程的分区表 B 决定（本工具不生成）：
· 槽位列表 —— 连接设备后自动读回，单选按钮指定启动槽
· 槽选择 GPIO（可选）—— 启用后按 引脚电平 % 槽数 选择启动槽，
  用于产线/现场用跳线切换固件版本（单引脚只能区分 2 个槽）
要增减 OTA 槽，请修改 examples/user_app_template/partitions_user_app.csv 后重新编译用户程序
局部烧录 「IAP 烧录文件」槽位可勾选不烧录的区域，保留设备上已有内容：
· 不烧 bootloader 0x0　· 不烧配置区 0x8000（默认勾选）
· 不烧分区表 A 0xB000　· 不烧 IAP 程序 0x10000
内置 IAP 镜像与手动选择文件两种模式下均生效
配置区布局2 个 4096 字节槽；每槽 = 28B 头部 + 612B 数据
分区布局v5 双分区表
固定区: iap_cfg 0x8000 (硬编码) / 分区表A 0xB000 / nvs 0xC000 / iap 0x10000
可变区: 分区表B 0x140000 / nvs 0x141000 / user_app 0x150000
分区表工具下方「分区表工具」可按 flash 容量生成并导出分区表 A/B（bin/CSV），
供用户程序工程使用。只有 user_app 分区大小随 flash 变化，其余分区固定
分区表修改规则 ✅ 允许：1. 修改 user_app 的 Size　2. 在 user_app 之后追加新分区
❌ 禁止：修改 user_app 起始地址 (0x150000) 之前的任何内容
在 user_app 之后追加分区可用于用户程序的文件系统 (LittleFS / SPIFFS / FAT)
救援进入 IAP已取消 flash 标志区（v5），改用：
A. 上电时按住 BOOT 键 (GPIO0) —— IAP 等待窗口内检测低电平
B. 等待窗口内向串口发送 iap 字符串
C. 用户程序主动请求（写 RTC RAM → 重启）
D. 断电重上电 —— 冷启动 RTC RAM 无效，默认进 IAP
写回策略写入槽 0（seq=1），槽 1 置为擦除态 0xFF
校验配置区：头部 CRC32 + 数据 CRC32（IEEE 802.3）
用户程序：由 bootloader 启动时自校验（magic 0xE9 / 段表 / SHA256）
直接烧录基于 Web Serial API + esptool-js，需 Chrome/Edge 89+
